# doc/ — результаты исследований

Значимые и проверенные на железе находки (RC2 + Lito X1).
Главный README проекта — [`../README.ru.md`](../README.ru.md) (RU) / [`../README.md`](../README.md) (EN).

- **[PROTOCOL.ru.md](PROTOCOL.ru.md)** / **[PROTOCOL.md](PROTOCOL.md)** — справочник по протоколу: карта
  loopback-портов, покадровая таблица FCC с именами параметров и хешами, keepalive, 4G, адресация параметров
  по хешу имени и проблема имён Lito X1, механика плавающего меню и accessibility, определение серийника и
  модели, доступ к логам полётов и записям экрана.

- **[config-table-commands.md](config-table-commands.md)** — полная группа команд доступа к параметрам FLYC,
  прогнанная на живом борту. Работают `03:F7` (метаданные по хешу: тип/ширина/min/max/default/имя), `03:FA`
  (сброс к дефолту, ровно один параметр — вопреки комментарию в `DiagServer.resetParam`), `03:E0` (1594 записи,
  `entries_crc`) и `03:E1` (структура по индексу, с именем); мертвы `03:FB` и `03:F0`. Главное: **статус 3 у F7 =
  «такого параметра нет»** — это ответ, а не тишина, и он снимает проблему имён Lito X1 (все три пары разделились
  чисто). `E0`+`E1` открывают дамп каталога **без Param Studio**. Раскладки кадров, коды статусов, ловушка с
  разным порядком лимитов в F7 и E1, обязательность корреляции по `seq`, замеры состояния борта и дрейф
  индексов между fw300/fw400. Маршрут не изменился — только 40007 wrapped.

- **[drone-link-detection.md](drone-link-detection.md)** — детекция подключён/отключён в матрице состояний
  (наш апп фон/передний план × DJI Fly stopped/фон/передний × a11y). Карта портов, что реально различает
  линк, дефект `LinkState` (40009 = housekeeping пульта, всегда «connected»), роль accessibility, матрица
  «состояние → детектор», рекомендации. Легло в основу `DroneLink` / `AuxReader` / `DroneLinkProbe`.
  - `assets/fly-hud-drone-connected.png` — скриншот лётного HUD DJI Fly: связь показана **графически**, не
    текстом (почему a11y-скрейп статуса связи ненадёжен).

- **[fcc-detection.md](fcc-detection.md)** — (негативный) поиск пассивного признака «FCC применён» в
  телеметрии 40007. Вывод: **чистого дискретного флага нет** — отличие FCC↔CE это континуальная мощность/
  энергия (`09:xx` HD-Link) + доступность 5.8 (в телеметрию не попадает); `07:19`/param-reads не отвечают;
  `03:5C` несёт `ce_country_type` (36/643), но только как event при смене региона. Все лиды (`02:81`,
  `02:87`, `09:3A`) опровергнуты A/B/A. Уточнено: **Apply FCC полностью live**, Restore CE — 5.8 по ребуту.

- **[fcc-autoapply-tests.md](fcc-autoapply-tests.md)** — тесты авто-применения FCC (keepalive) по сценариям
  (пульт→дрон / дрон→пульт / релинк, при нашем аппе vs DJI Fly на переднем плане) и вызванные ими правки:
  фикс гейта `awaitLink` (слепой фолбэк на 40009, video-safe), batch-чтение откатано в пользу per-param +
  строгий обрыв, ускорение релинка (`BLIND_APPLY_MS` 10с), доказанное ограничение «Fly bg vs stopped»
  (usage-stats не различает), инверсия Cine/ATTI, итоговые константы и матрица сценариев.
