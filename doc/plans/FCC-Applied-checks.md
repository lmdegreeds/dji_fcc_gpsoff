# План: признаки «FCC успешно применён» при нашем приложении на переднем плане

## Context

Нужен машиночитаемый признак «FCC сейчас активен / применён корректно» — прежде всего для режима,
когда **наше приложение на переднем плане** (тогда страницы «Передача» DJI Fly не видно, a11y-скрейп
её невозможен). Вторично — для режима **Fly на переднем плане** (там у пользователя уже есть визуальный
оракул: выбор 2.4/5.8/двухполосная + график мощности).

**Уточнения пользователя (правят наши источники):**
1. **FCC применяется без ребута дрона** (ребут, возможно, нужен только в первый раз) — значит разница
   FCC↔CE **наблюдаема в реальном времени** в телеметрии.
2. **На прошивке v400 5.8/двухполосная тоже работают.** README/07-models утверждают обратное — **правка
   источников** (см. ниже).

**Что уже проверено на этом железе (почему нужен пассивный сигнал):**
- `07:19` country (`FccCountry.read` → 40009) — стабильно «no reply».
- Активные param-reads `03:F8` на 40007 (`ParamRead`/`FlightState`) — не отвечают (`readsWork=false`,
  `/readparams` = no answer). Значит `ce_regulatory_level`/`ce_country_type` напрямую не прочитать.
- 40009 пассив (`06:AE`/`00:81`) — не менялся при дрон on/off; про FCC↔CE пока не мерили.
- Реальные признаки живут на **40007 OSD** (плотный FLYC/RF-поток) — его при нашем аппе на переднем
  плане читать безопасно (Fly в фоне, видео никто не смотрит).

Точное поле-дискриминатор **неизвестно** до захвата FCC-on vs CE — поэтому план начинается с
эксперимента-поиска, а дизайн признака зависит от его результата.

## Oracle (ground truth для валидации)

Страница **«Передача» DJI Fly** через a11y-скриншот (`/screen`): наличие выбора **2.4 / 5.8 /
двухполосная** и максимум **графика мощности**. Управляемый стимул — переключение **Apply FCC** (`/fcc`)
↔ **Restore CE** (`/ce`) с наблюдением, как меняется страница (раз ребут не нужен — сразу).

## Phase A — эксперименты по поиску пассивного сигнала (нужно железо)

Условие: наш апп на переднем плане, дрон ON, a11y ON. Для каждого эксперимента снять **два состояния —
FCC-on и CE** (через `/fcc` и `/ce`), и сравнить.

- **E1 (40007 OSD — основной кандидат).** `/capstart?port=40007` → `/capframes` (или `/cap?port=40007&ms=`),
  распарсить wrapped-кадры (как в `doc/drone-link-detection.md` §3), найти inner-поле, флипающееся FCC↔CE:
  кандидаты — SDR/RF link-status, кадр с текущей частотой/каналом/band, поле TX-мощности (то, что рисует
  график «Передача»). Опереться на `RadioLinkMonitor`-подход (tally по cmdSet:cmdId + last payload).
- **E2 (40009 пассив).** `/radiolink` + `/cap?port=40009` в FCC vs CE — вдруг байт региона/мощности
  флипается в `06:AE` или в новом `07:xx`/`06:xx` кадре.
- **E3 (07:19 при нашем аппе fg).** Замерить hit-rate/значение `/country`, когда наш апп на переднем
  плане (вдруг роутится лучше, чем при Fly-fg) — дешёвый бонус-сигнал, если ответит.
- **E4 (a11y-оракул).** `/screen` на странице «Передача» в FCC vs CE — зафиксировать, какие тексты/
  элементы флипают (валидирует оракул и даёт вторичный признак для Fly-fg).

Выход Phase A: конкретный (порт, cmdSet:cmdId, offset, значения FCC vs CE) для признака.

## Phase B — дизайн признака (зависит от Phase A)

- **Основной путь (найдено пассивное поле):** новый детектор `FccState` по образцу
  [DroneLink.kt](../../projects/dji/dji-fcc-gpsoff/app/src/main/java/com/dji/fccgpsoff/DroneLink.kt) /
  [RadioLinkMonitor.kt](../../projects/dji/dji-fcc-gpsoff/app/src/main/java/com/dji/fccgpsoff/RadioLinkMonitor.kt):
  кормится из [DumlNative.onNativeFrame](../../projects/dji/dji-fcc-gpsoff/app/src/main/java/com/dji/fccgpsoff/DumlNative.kt#L77),
  читает поле, отдаёт `state(FCC/CE/unknown) + ageMs + statusJson`; эндпоинт `/fccstate`; индикатор в UI.
  Работает при нашем аппе на переднем плане (кормится через aux, который уже поднимает `DroneLinkProbe`
  когда Fly не на переднем плане).
- **Фолбэк:** если пассива нет, но E3 показал, что `07:19` роутится при нашем аппе fg → тонкая обёртка
  над `FccCountry.read()` (`AU`=FCC), honest-null при no-reply.
- **Вторично (Fly-fg):** a11y-скрейп «Передача» — либо новый эндпоинт «dump visible labels» из
  [DjiFlyAccessibilityService](../../projects/dji/dji-fcc-gpsoff/app/src/main/java/com/dji/fccgpsoff/DjiFlyAccessibilityService.kt)
  (матч «5.8»/«двухполосная»), либо скриншот-проверка. Zero-bus. Не основной таргет.

## Phase C — сценарии валидации (список пользователя)

Прогнать выбранный сигнал (в режиме нашего аппа fg) против оракула (страница «Передача» при Fly-fg) в:
1. **Пульт → дрон** (сначала RC, потом дрон).
2. **Дрон → пульт** (сначала дрон, потом RC).
3. **Повторное выкл/вкл дрона** при включённом пульте и **Fly на переднем плане** (проверка авто-применения).
4. **Авто-apply keepalive** — landing после (ре)линка.

Для каждого фиксируем: значение сигнала ↔ состояние оракула, чтобы подтвердить, что признак совпадает с
реальностью в обоих режимах.
