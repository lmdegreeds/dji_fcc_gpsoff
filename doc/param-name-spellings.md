# Как называется параметр на борту (2026-08-20)

**Записано 2026-08-20** по разбору лога и скриншотов пользователя с DJI Air 3
(прошивка неизвестна, приложение 1.1.0, пульт DJI RC 2, серийник борта
`1581F6N8C237D0031SNN`).

## Находка: имя параметра может быть составным

Прошивка Air 3 отдаёт по `03:E1` имя параметра **одной строкой с вертикальной
чертой**:

```
gps_enable|g_config.gps_cfg.gps_enable
forearm_led_ctrl|g_config.misc_cfg.forearm_lamp_ctrl
```

То же самое лежит в экспорте DJI Param Studio для этого борта
(`params_example/dji air3 dh v1.dhp`, поле `"name"`). У Lito X1 черты нет —
там просто `gps_enable`.

Это важно потому, что параметр **адресуется хэшем от имени**
(`native/duml_core.cpp`, `param_hash`: `name + "_0"`, затем
`h = ((h << 8) | b) % 0xFFFFFFFB`). Три написания — три разных адреса:

| написание | hash |
|---|---|
| `gps_enable` | `9d8a8881` |
| `g_config.gps_cfg.gps_enable` | `829542c5` |
| `gps_enable\|g_config.gps_cfg.gps_enable` | `c2e4c359` |

## Что видно в логе пользователя

Лог `tmp/duml-1787241813124.log.txt`, 2026-08-20, 02:00–02:02:

* `02:00:10.508` и `02:00:11.093` — два запроса `03:F8` по `9d8a8881`
  (`gps_enable`). Третьей попытки нет, и следующий параметр начали читать через
  168 мс после второй — то есть **вторая вернула ответ**. Это единственное
  положительное чтение во всём логе.
* `02:01:58.859`, `02:01:59.541`, `02:02:00.125` — три запроса `03:F8` по
  `c2e4c359` (составное имя, из редактора параметров), все три отработали полное
  окно 500 мс **без ответа**.

Одна выборка, не доказательство: окно на 40007 отвечает примерно в 70% случаев, а
в эти секунды FCC-keepalive долбил 40009 каждую секунду. Но направление такое:
**на этом борту короткий алиас отвечает, а составное имя — нет**.

Проверять надо `03:F7`: у него статус 3 = «нет такого параметра» — единственный
настоящий отрицательный ответ на этой шине.

```
curl -s "http://<rc>:8899/params/info?name=gps_enable"
curl -s "http://<rc>:8899/params/info?name=g_config.gps_cfg.gps_enable"
curl -s "http://<rc>:8899/params/info?name=gps_enable%7Cg_config.gps_cfg.gps_enable"
```

## Что сделано в 1.1.2

Ни одно из трёх написаний не выбирается наугад — приложение **спрашивает борт**:

* `ParamName` — разбор `a|b` и список кандидатов (`ParamName.candidates`);
* `ParamMeta.resolve` — все написания уходят `03:F7` **в одном окне 40007**
  (потери на этой шине пооконные, поэтому три запроса стоят столько же, сколько
  один);
* `ParamAlias` — запоминает, какое написание борт подтвердил, на сессию;
  `preferred` переносит вывод на весь каталог;
* `ParameterAddress.key` — «логический» параметр теперь адресуется составной
  формой, а `name()` возвращает **измеренное** написание, если оно есть, и только
  иначе — то, что говорит профиль Lito/g_config.

Побочный, но важный результат: `ParamMeta.info` больше не выбрасывает ответ борта,
если каноническое имя в ответе не совпало со строкой запроса. Раньше сравнение было
`parsed.name != name`, и на Air 3 это отбрасывало **каждый** удачный `03:F7`:
борт отвечает своим составным именем, которое по определению не равно алиасу, о
котором спросили.

## Что это НЕ значит

Переключатель «Имена Lito / g_config.*» не отменён. Он остаётся, когда борт не
ответил ни на что: тогда писать всё равно надо чем-то, и профиль — единственное,
что есть. Но теперь приложение честно пишет в лог, откуда взялся адрес:

```
write gps_enable#9d8a8881 = 00 · p40008 · 2/2 frame(s) out · address measured on this aircraft
write gps_enable#9d8a8881 = 00 · p40008 · 2/2 frame(s) out · address from the Lito profile (not verified on this aircraft)
```

## Открытый вопрос

Индексирует ли прошивка **оба** алиаса или только один — неизвестно. Если оба, то
`03:F7` по любому из них ответит Ok, и `ParamAlias` возьмёт первый ответивший; это
безопасно. Если борт отдаёт Ok только на составную форму, `ParameterAddress.name()`
вернёт её, и профиль Lito/g_config для этого борта окажется просто ни при чём —
приложение так и напишет в лог.

Ответ даст первый же лог с Air 3 на 1.1.2: строка
`param name: '<key>' → the board indexes '<spelling>#<hash>'`.
